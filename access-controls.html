Access Controls

Quick refresher

Authorization decides whether a principal may perform an action on a resource under the current conditions. Deny by default and enforce decisions on the server at each protected operation, including lists, exports, and background jobs.

Worked example

In the expense app, employees can read their own claims, managers can approve eligible claims for their team, and finance can export authorized records. The API checks the authenticated principal, the action, the claim's tenant and owner, and the current policy.

Read the sign-in flow in Authentication

Choose a policy model

ACLs attach permissions to individual resources. RBAC assigns permissions through roles. ABAC evaluates attributes such as tenant, department, or resource classification. Relationship-based policies can express ownership or membership. Combine models where the business rules call for it.

Enforce scope consistently

Evaluate the trusted principal and target resource at the server boundary. For a list or search, apply the appropriate authorization scope to the query. For a write, account for state changes between the decision and the mutation. Use a shared policy implementation where paths need identical semantics.

Handle workload access and revocation

Give automation its own identity with narrow permissions. Decide how quickly revoked access must take effect, including policy caches, queued tasks, and existing sessions. Log grant and revoke events with actor, target, permissions, and timestamp.

Build a policy test matrix

Cover own and other users' resources, tenant mismatch, missing and expired roles, role removal, list filters, exports, and direct API requests. Exercise allow and deny decisions and test that denied actions leave state unchanged.

Interview practice

How would you design permissions for the expense app?

List the protected actions and principals. Use roles for broad capabilities and resource attributes for tenant and ownership checks. Enforce policy at the API and in background jobs. Test cross-tenant denial, revocation, and audit coverage.

When would you use resource attributes with RBAC?

When a role defines a capability but does not determine which objects it applies to. Managers can have the approve capability, with department and claim attributes limiting which approvals they can perform.
